## 提示词正文

你现在负责实施“医院等级评审系统 v0.2”。这是一个**生产导向、本地数据版**：当前没有真实医院数据、真实接口、统一身份系统和部署环境，所以必须使用虚构医院与合成数据完成开发和验收；但是系统的领域模型、权限、安全、接口、数据库、文件、审计和运维边界必须按未来真实医院落地的方向设计。不要把“当前不能接真实数据”理解成可以采用一次性演示代码。

`交接文档.md` 是多人共享的唯一主交接入口。历史记录与当前事实可能分节保存；当前运行和验证结论以交接文档第 7 节最新记录为准，计划和下一步方向以 `docs/next-version-plan.md` 为准。

### 二、用户目标和不可突破的边界

- 目标是把系统尽可能做成未来可落地的医院评审平台，而不是继续堆叠静态演示页面。
- 当前仍是本地开发和本地验收：不连接真实医院，不接触真实患者数据，不发布公网，不修改服务器，不创建真实接口凭据。
- 合成数据必须位于 seed/demo/adapter 层，不能写进核心业务规则作为唯一实现。
- H2 文件库、`X-Demo-Role`、本地附件目录、演示账号只能在 demo profile 使用；生产 profile 必须能拒绝它们。
- 不把商业宣传、GitHub 项目或合成数据当作政策依据。政策口径优先来自工作区原始政策和国家卫健委正式文件。
- 不把测试通过、浏览器显示正常或接口模拟成功写成“已上线”“已符合生产安全”“已接通真实系统”。
- 不删除、覆盖或重写其他 AI 的未完成修改；不要执行全工作区 `reset`、`clean` 或删除未知文件。

### 三、领取任务和共享工作区规则

开始修改前，先在 `交接文档.md` 的任务表新增或更新一行，写清：

- 任务编号和负责人；
- 允许修改的文件/目录；
- 依赖的接口契约；
- 当前状态（进行中）；
- 预计验证命令。

同一文件只能有一个活跃写入者。若发现目标文件已有其他 AI 的未完成修改，应先缩小范围或记录冲突，不得覆盖。共享接口必须先更新 `docs/next-api-contract.md`（若尚未建立，则先创建它），再同步后端、前端和测试。

### 四、建议实施顺序

按 `next-version-plan.md` 的阶段推进：

1. **生产边界与契约**：定义标准、条款、任务、材料、批次、质量报告、周期、快照比较、认证上下文、租户范围和统一错误码。
2. **领域模型拆分**：把当前 `SyntheticData` 的平行数组改为结构化的指标定义；把过大的 `DemoService` 拆成标准、任务、证据、质量、计分、审计等领域服务。
3. **标准与条款**：标准包版本、生效期、来源定位、章节/条款/指标/前置关系、导入校验、发布后只读和新版本修订。
4. **任务与权限**：条款分派到医院/科室/岗位/人员，服务端范围校验，状态机、逾期、退回原因、幂等和审计。
5. **证据资料库**：材料版本、SHA-256、对象关联、审核、有效期、下载授权、非法文件拦截；预留 S3 兼容存储，当前使用本地替身。
6. **数据质量与周期试算**：`DataSource → CollectionBatch → MetricFact → CalculationTrace`，CSV/JSON/合成适配器，4 年周期，失败批次阻断，结果快照不可变。
7. **整改闭环与报告**：问题来源、根因、措施、责任人、效果指标、复核结论、证据链、DOCX 快照报告和两次试算对比。
8. **生产形态基础设施**：PostgreSQL migration 草案、H2 契约测试、OIDC/LDAP 接口、医院/科室租户上下文、结构化日志、关联 ID、健康检查、备份恢复和本地替身。
9. **前端工作台**：周期进度、待办逾期、短板、证据缺口、条款树、任务台、材料版本和报告中心；前端菜单隐藏不能替代后端权限。

### 五、必须遵守的实现原则

- 先写失败测试，再实现功能；不要先写代码再补一个只验证 happy path 的测试。
- 标准发布版本、评审结果快照、材料版本、审计记录不可覆盖删除；更正使用新版本、冲正或新批次。
- 所有指标结果必须能追溯到来源批次、口径版本、计算规则、执行时间和操作者。
- 写接口要有幂等/重复提交保护，并在成功后重新读取后端状态形成真实回执。
- 列表、导出、批处理、异步任务都必须带医院/科室/角色范围；不能只依赖前端筛选。
- 领导、观察员和默认导出不能看到患者级字段；病案号等标识必须脱敏或使用内部引用。
- 文件名不能直接拼接路径；拒绝 html/svg/js/exe 等非允许文件；真实存储路径不能暴露给前端。
- 不修改已发布迁移；生产数据库使用追加迁移。H2 只是测试实现，核心业务不能依赖 H2 特有行为。
- AI 功能若以后加入，只能做检索、解释或待办草稿；任何写入都要人工确认、权限校验和回查。

- 浏览器至少完成一条“条款 → 任务 → 材料 → 数据质量 → 整改 → 报告”链路。

没有实际运行的命令不得写成“通过”。如果某项因缺少真实数据或外部服务只能使用替身，必须写明替身范围和真实接入前的剩余工作。

### 七、交付和交接格式

完成后在 `交接文档.md` 追加一条变更记录，并至少写出：

1. 已完成的功能和未完成的功能；
2. 实际修改的文件范围；
3. 接口契约是否变化；
4. 数据迁移、配置和回滚方式；
5. 实际执行的命令及通过/失败/跳过数量；
6. 当前运行进程、端口和复现步骤；
7. 已知风险、生产落地前仍需要用户提供的资料；
8. 下一位 AI 应先读什么、从哪里继续。

最终结论必须使用以下三种表述之一：

- “本地演示/合成数据范围已验证”；
- “生产形态接口/替身已验证，真实接入未验证”；
- “真实生产环境已验证”（只有用户明确提供真实环境并完成相应验收时才允许使用）。

不要把第一种或第二种表述升级成第三种。
