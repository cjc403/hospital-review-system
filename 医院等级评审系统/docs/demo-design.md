# 医院等级评审演示系统设计

> 2026-11-03 用户新要求：界面采用正式业务名称，移除账号姓名的演示后缀及全局演示/合成标注。此显示约定覆盖下文旧标注要求；数据来源和本地运行范围仍如实保留在开发文档，账号标识、权限、统计和历史数据不变。


## 目标与边界

基于既有 01–05 文档开发本地可操作演示。虚构“江城市第一人民医院”，展示从指标监测到数据核查、自评、改进和报告的闭环。用户已明确先开发演示系统，不处理真实落地。原始资料不改动。

成功条件：可一键启动；浏览器中可筛选、下钻、提交/审核补录、查看数据差异、发起抽查、维护前置结论、模拟等次、推进改进单和下载报告；刷新和后端重启后业务修改保留；能恢复初始演示数据。

## 实现选择

- 选择：Vue 3 + TypeScript + Vite + ECharts，Java 17 编译目标、Spring Boot 3.5 + H2 文件持久化。用户已授权直接开始；内嵌数据库为本轮工程决策。
- 纯静态原型启动简单但难以演示后端校验和持久化；不采用。
- 完整 PostgreSQL/真实 ETL 贴近落地，但增加不属于本轮的环境和接口负担；暂缓。
- H2 内存只用于测试；开发/演示使用文件库，事务保存一份演示状态快照，由独立 Repository 封装。无需将简化存储冒充正式主题库。

## 页面与体验

统一中文管理工作台。深蓝侧边导航、浅灰背景、白色卡片、蓝/青色强调；图表与表格优先，不使用无关装饰图片。全局显示演示标记、数据周期、角色切换。

页面：评审总览、指标监测（筛选/趋势/科室/脱敏成员抽屉）、数据核查（病案差异和条款抽查分栏）、补录审核、前置自评、模拟等次、持续改进、政策文件、运行与审计。页面必须有加载、空结果、错误反馈和提交防重复状态。

## 数据与规则

使用 12–16 个具代表性的样例指标，覆盖五个监测章节和高优/低优、自动/人工、月均/年末/DRG 汇总等情况。提供近 12 个月趋势、2023–2026 年度值、6 个临床科室，以及 29 条前置要求加数据真实性系统条款。所有数字明确为合成示例。

计分函数独立：奇偶中位数；规模类同时检验中位数与最后一年；连续类按项目约定统计变好/变坏次数，变差取最差年；空值不纳入；比例 90/80/70%；前置不符合或抽查错误率 >10% 时延期。样例覆盖不足 60%，任何等次始终为试算。

病案差异不计入条款错误率。条款偏差 >=10% 为错误，但错误条款率须 >10% 才触发延期；相对偏差的基准是 homeValue，home=0 时相等为0，否则为1。新抽查记录不可覆盖旧记录。

补录提交后由质控角色审核；通过只生成独立人工批次/覆盖标记，保留自动值，重复审核拒绝。月结重跑产生新批次，旧批次保留。

前置 compliance 与 workflow 分开。系统数据真实性结论由最新抽查驱动，不得人工改为符合。unknown 不算确认符合；试算明确提示未完成前置复核。

改进状态：opened→assigned→doing→evidence_ready→verified→closed；closed 只允许质控 reopen；证据就绪需要措施和附件；关闭 improved 要求后续周期值改善，否则需 not_recovered 与说明。

政策上传本轮仅维护登记元数据和影响说明；涉及 scoring_rule 的记录 blocked，禁止确认。佐证采用真实本地文件上传，限制类型和大小，绑定业务对象。

报告导出为真实 DOCX，绑定一次 scoreRun 与当次前置/抽查快照，引用固定的年度计算数据。报告显著写“演示试算”。

## 本轮简化

不实现生产登录、统一认证、源数据库连接、真实 DRG 分组、生产 SQL 执行、外部消息、公网部署。角色通过 X-Demo-Role 标头演示，不能视作安全边界。代码和文档必须说明此点。

## 验证

先编写并运行失败的计分/业务测试，再实现。后端验证持久化、校验和状态转换；前端运行类型检查/构建及关键交互测试；集成验证 API、报告 ZIP、重启保存及浏览器实际操作。最终由独立 AI 复核。
