## 必须修复的问题

### P1：试算详情接口违反自身契约

位置：

- backend/src/main/java/cn/demo/review/v2/score/ScoreService.java:222
- frontend/src/v2/types.ts:210
- docs/next-api-contract.md 第 6 节

创建试算时，yearValues 在内存中是数组；写入 score_item.year_values 后，读取接口直接返回数据库字符串。契约要求 yearValues 是年度对象数组，前端 v2 类型目前也把它声明成字符串，导致前后端和契约三者不一致。当前集成测试只检查项目数量，没有检查字段形状。

修复要求：数据库可继续存稳定序列化格式，但 GET 接口必须反序列化为结构化数组；前端类型、组件和测试同步修正，并增加接口字段形状回归测试。

### P1：drg_formula 没有按定义实现

位置：

- backend/src/main/java/cn/demo/review/v2/score/ScoreService.java:117-121
- backend/src/main/resources/standards/demo-standard-v1.json 中 i11 的 annualAgg: drg_formula

当前只对 year_end_snapshot 特殊处理，其余类型都走月度平均。因此 drg_formula 被错误地按平均值计算。标准包已经声明该演示指标应读取预置年度 DRG 汇总值，不能把平均值冒充 DRG 计算。

修复要求：为 drg_formula 建立明确的合成年​​度汇总事实或独立聚合器；没有输入时返回缺失/不适用，不能静默退化为平均值。增加年度聚合单测和 API 回归。

### P1：试算快照引用了周期外的已应用批次

位置：

- backend/src/main/java/cn/demo/review/v2/quality/QualityService.java:279-282
- backend/src/main/java/cn/demo/review/v2/score/ScoreService.java:73-74,164

appliedBatchIds() 返回本院所有已应用批次；试算的事实查询虽然按年份过滤，但 snapshot.batchIds 保存了所有批次 ID。因此周期为 2023–2026 的报告可能声明引用 2027 年批次，破坏数据血缘和报告解释。

修复要求：按评审周期、标准版本、医院范围筛选实际使用的批次；快照只保存参与计算的批次。增加周期外批次不进入快照的回归测试。

## 重要但可后续修复的问题

- CSV 适配器使用简单 split(",")，不支持带引号、逗号转义和换行的合法 CSV；真实接入前需要标准 CSV 解析器和编码/大小边界。
- TokenAuthenticator 目前故意拒绝所有 token，接口边界已经存在，但真实 OIDC/LDAP 尚未实现。
- SchemaMigrationTest 使用 H2 PostgreSQL 模式；真实 PostgreSQL 临时验证有交接记录，但本轮未重新启动隔离 PostgreSQL。
- v0.2 浏览器人工走查未执行，前端只做了类型检查、构建和逻辑测试。
- scripts/verify.ps1 没有把 v0.2 服务启动、接口链路和生产 profile 检查作为独立阶段；目前主要依赖 Maven 测试和手动集成脚本。

## 通过项

- 生产 profile 拒绝 X-Demo-Role，无有效 Bearer token 返回 401。
- demo 角色映射到服务端医院、科室和角色上下文。
- 跨医院对象返回 404，科室负责人只能访问本科室。
- 标准导入校验、发布不可变、修订生成新版本。
- 任务分派按 hospitalId/requestKey 幂等，状态机和终态不可变。
- 材料版本递增、SHA-256、同内容幂等、危险扩展名和魔数校验、旧版本下载。
- 质量错误批次被阻断，应用一次，重放生成新批次。
- 试算快照和 DOCX 重下载字节稳定。
- 前置不符合、条款抽查错误率和延期原因可验证。
- 审计事件带 X-Request-Id，没有把令牌和服务器路径写入日志。
- CSV/HTTP JSON 适配器只输出白名单指标字段，未配置来源不会假装可用。
