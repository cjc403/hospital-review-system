## 1. 当前已具备（本地已验证）

- 契约：`docs/next-api-contract.md`（v0.2 25+ 端点、错误码、授权矩阵、范围与不可变规则）。
- 身份边界：`review.profile=demo|prod`；prod 拒绝 `X-Demo-Role`、无令牌即 401；启用 Spring prod profile 却未设 `review.profile=prod` 时**启动失败**。
- 授权矩阵：review_office / leader / dept_head / indicator_admin / evidence_admin / observer；医院为租户边界、科室为范围边界，服务端强制。
- 不可变对象：标准发布版本、已应用批次、试算快照、材料版本、审计事件均无修改/删除端点。
- 数据链：`DataSource → CollectionBatch → MetricFact → CalculationTrace`，7 类质量规则，错误批次阻断。
- 证据：版本 + SHA-256 + 审核 + 下载授权 + 危险文件/魔数拦截；存储走 `BlobStore` 接口（当前本地目录实现）。
- 迁移：`V2Schema` 版本 2（H2 与 PostgreSQL 同构 DDL），`db/migration/postgresql/V2__v02_core.sql`。
- 可观测性：`X-Request-Id` 贯穿过滤链与审计；`/api/health`；结构化错误体。
- 验证：后端 55 项、前端 29 项、集成检查 17 组（v1 七组 + v0.2 十组）；PostgreSQL 与备份恢复已在临时隔离集群验证。

## 3. 需要用户提供（按优先级）

1. **隔离 PostgreSQL 实例**（库名、账号、口令）——用于执行迁移、备份恢复与生产 profile 启动验证。请勿提供生产库账号。
2. **身份方式**：OIDC（issuer、client_id/secret、claim 映射）或 LDAP/AD（地址、base DN、属性映射）。
3. **组织与人员**：医院标识、科室编码与名称（用于 `dept_map`）、岗位字典。
4. **数据字典与样例**：病案首页、床位日、手术、人员、感控、DRG 结果的最小字段集与 3–5 条脱敏样例。
5. **材料存储**：对象存储类型与访问方式；材料保留期限。
6. **安全要求**：等保级别、日志留存期限、患者标识脱敏规则、导出审批流程。
7. **验收方式**：验收环境网络、验收账号、验收口径（是否按科室/章节抽检）。
