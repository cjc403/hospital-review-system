## 组会建议路线（约五分钟）

1. `review.admin`：展示“我的工作台”，进入评审作业台查看标准、任务、证据，再到 v3 查看指标、血缘和报告。界面使用正式业务名称。
2. 退出后用 `surg.staff`：展示普通外科身份、本科室任务及补录入口，说明联络员只有执行权限。
3. 换 `surg.director` 或 `medical.reviewer`：展示本科室待审任务的受理/退回按钮，对比执行与审核。
4. 换 `expert.demo`：仅有工作台和标准/任务/材料页签，任务仅 CARD 的两类授权条款。
5. 换 `sys.admin`：账号目录展示九类角色和六科室。可打开新增/编辑表单说明授权项，保护自己的权限和最后一个管理员。
6. 如需说明隔离，换 `h002.leader`：显示第二医院的少量数据，不能看到 H001 历史。

所有业务按钮会产生实际持久化演示记录；已应用批次、报告快照、材料版本和审计历史仍按原规则保留。已有业务数据已在升级前备份，没有执行演示重置。

## 账号和会话行为

- 当前标签页保存会话，刷新后恢复；退出即时清理身份与页面缓存。
- 会话有效期八小时；停用、改角色、改科室/条款、改密、管理员重置密码后，旧会话失效。
- 连续输错密码五次，暂锁六十秒；管理员重置密码也能解除锁定。
- 密码采用独立盐 PBKDF2 哈希，数据库仅保存会话令牌的 SHA-256，不返回或记录密码/令牌。
- 菜单、页签和按钮依据后端权限开放；直接访问接口、下载附件同样执行授权。
- `X-Demo-Role` 不能替代正常登录。旧头兼容开关只供旧契约隔离测试；正常启动不启用。
- 真实 OIDC/LDAP、真实医院数据源、生产部署、目标 PostgreSQL 与性能容量均不在本次已验证范围。

接口和逐项权限以 `auth-api-contract.md` 及后端 `RolePermissions` 为准。验收实绩见主交接文档第 7、9 节。
