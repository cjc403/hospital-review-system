# 医院等级评审演示系统 Implementation Plan

> For agentic workers: use the shared handoff and task ownership. Backend and frontend are independent under the frozen API contract. Implement each task test-first where behavior warrants tests; root integrates and commissions an independent final review.

**Goal:** 交付可在本机启动、持久化且可完整操作的医院等级评审演示系统。

**Architecture:** Vue 工作台通过 REST 调用 Spring Boot。后端将演示领域状态事务保存到 H2 文件库；计分纯函数独立，文件附件单独存储。前后端共享 api-contract.md。

**Tech Stack:** Java 17 target / Spring Boot 3.5 / H2；Vue 3 / TypeScript / Vite / ECharts。

**Spec:** ../../demo-design.md 与 ../../api-contract.md；根目录交接文档记录用户最新约束。

## Global Constraints

- 全部数据合成，所有页面标记演示，模拟等次始终 trial=true。
- 端口18080/18173，127.0.0.1；不发布、不连接真实医院。
- 不修改原始01–05和政策文件；多个AI按目录分工。
- 错误状态有明确中文提示；关键写入必须后端持久化。
- 日期与默认演示周期固定，避免运行日期改变验收结果。

## Review Focus

- 空分母/空年度不产生错误符合率；全空结果不给正式等次。
- 10%条款错误率边界与病例差异不混淆。
- 重复提交、非法状态、角色限制在后端验证。
- 报告绑定快照，不受后续编辑影响。
- 重启保留、重置可恢复；文件上传与下载不允许路径穿越。
